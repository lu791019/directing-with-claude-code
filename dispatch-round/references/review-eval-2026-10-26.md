# Review 規則實測（2026-10-26）

依〈Solving code review at Anthropic〉改了 `code-review.md`（分級標籤、回報格式、收斂上限、獨立 review）與新增 `REVIEW.md`。
文章的數字（54% PR 有實質意見、輪數 2.08→1.32）是 Anthropic 內部的，我們無法重現；這裡驗的是**機制在我們的環境做不做得到**。

## Fixture

小型 Python repo（退款功能），預埋答案已知的問題：

| 代號 | 類型 | 內容 |
|---|---|---|
| N1 | 新引入 | 累計退款可超過已付 |
| N2 | 新引入 | `days > 29` 擋掉第 30 天（規格含第 30 天） |
| C1–C3 | 同類 bug | 金額變 float，散在 2 個檔共 3 處 |
| P1 | 既有 | `subtotal_cents` 用 `items[1:]` 漏第一項（PR 沒改到的行） |
| V | 應跳過 | `vendor/` 裸 except |
| N3 | 第二輪修正引入 | 先 `+=` 再檢查上限，被拒時訂單已被改掉 |

全部 reviewer 用 Sonnet、同一份 prompt（只差規則來源），只讀不改。

## 第一輪（各 2 次）

| 指標 | 舊規則 | 舊規則＋REVIEW.md | 新規則＋REVIEW.md |
|---|---|---|---|
| N1、N2 抓到 | 2/2 | 2/2 | 2/2 |
| 同類 bug 列出實例 | 3/3 | 3/3 | 3/3，**附搜尋指令** |
| P1（既有）被提出 | **0/2** | **0/2** | **2/2，正確標「既有」不擋** |
| 第一行計數 | 無 | 無 | 有 |
| 附 `檔案:行號` | 只寫函式名 | 只寫函式名 | 有（行號抽查正確） |
| 小意見數量 | 3–4 則＋immutability 說教 | ≤2，遵守「不提 immutability」 | ≤2 |

## 第二輪（修正 commit 後各 1 次）

| 指標 | 舊做法：重審整個 PR | 新規則：只審修正 diff＋已提清單 |
|---|---|---|
| N3 抓到 | ✅ | ✅ |
| 發現總數 | 7 | 2 |
| 重提第一輪已提過的 | 4（`x` 命名、ratio 驗證、immutability、測試缺口） | 0 |

## 結論

- **抓 bug 的能力沒變**：小 fixture 上舊規則已經全抓，新規則沒有讓召回率變好，也沒變差。
- **新規則的價值在分流與收斂**：既有問題從「完全沒人提」變成「提出但不擋」，第二輪雜訊從 7 降到 2 且零重提——對會照單全修的 agent 作者，這就是少一輪。
- **REVIEW.md 單獨就有效**（小意見上限、跳過路徑、repo 特有的不提項都被遵守）；格式與既有分級要靠 `code-review.md`。

## 實測撞到的坑

1. **同一 session 改全域規則，子代理看不到。** 子代理拿的是主 session 開場時的 rules 快照；探針問欄位名，回的是舊表格。
   要在同 session 內驗新規則，派工單要明寫「先 Read 規則檔，以檔案為準」。新 session 不受影響。
2. **reviewer 只看 diff hunk 就抓不到既有問題**（4/4 漏 P1）→ 規則加「被改到的檔要整份讀」，之後 2/2 抓到。
3. **reviewer 還在讀檔時別動它的工作區**：本次差點因在同目錄 commit 第二輪修正而汙染第一輪結果（輸出的程式碼與 `2 passed` 證實讀檔早於 commit，結果保留）。第二輪 fixture 應另開副本。
4. `risk-paths` 用 `git diff <base>` 會把 base 在分岔後的前進也算進來（某 repo 實測誤報 55 檔）→ 改從 `merge-base` 比，已加回歸測試。

## 限制

- 每組 n=1～2、單一 fixture、單一模型，只能說「機制可行」，不能說「效果幅度」。
- 第三輪熔斷沒有實測（fixture 兩輪就收斂）。
- 真實的漏抓率要靠之後 walkthrough 的「漏抓檢討」表累積。

## 追加：把「整份讀檔」從流程步驟改成輸出欄位（同日晚間）

全新 session、不提醒讀規則、同一 prompt：

| 版本 | 有寫讀檔範圍 | 抓到既有 P1 | 計數與列出相符 |
|---|---|---|---|
| 規則只寫「要整份讀」（流程步驟） | — | 1/4 | 3/4 |
| 回報第二行必填「讀檔範圍：整份讀了…；只看 diff：…」 | 4/4 | **4/4** | 4/4 |

格式要求比流程步驟更容易被遵守：要求「寫出你讀了什麼」，模型就會真的去讀。
副作用：同類 bug 的實例有時被拆成多則「重要」列出（不是新雜訊）；1/4 次行號偏差數行，引用前仍要抽查。
