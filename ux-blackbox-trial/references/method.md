# 方法與實證

調整編制、判準或流程前先讀這份。以下判斷來自實際試跑的經驗，數字不收錄；請用自己的試跑結果校準。

## 為什麼這樣分工

| 角色 | 看什麼 | 抓得到 | 抓不到 |
|---|---|---|---|
| UX 挑剔（L1、L2） | 只看畫面，照任務操作 | 走不下去、沒回饋、入口找不到、路徑繞遠 | 訊息過多、資訊層級 |
| UI 視覺（L3） | 只看畫面，每個狀態截圖逐項檢查 | 截斷、錯位、不一致 | 是否符合規範 |
| 白箱（W1） | 讀原始碼、規範、設計稿 | 違反規範、缺狀態、缺鍵盤路徑 | 實際操作才看得到的問題 |
| 協調窗（你） | 核對全部 | 判定真假、去重、定嚴重度 | 好不好用 |

## 預設編制

| 編號 | 面向 | 模型 | 思考程度 | 理由 |
|---|---|---|---|---|
| L1 | UX 挑剔 | Opus | low | 精確率較高，多輪結果一致 |
| L2 | UX 挑剔 | Sonnet | medium | 曾抓到 L1 沒抓到的發現，保留作對照 |
| L3 | UI 視覺 | Opus | low | 與 W1 幾乎不重疊，兩者互補 |
| W1 | 白箱規範 | Opus | medium | 精確率穩定；早期的誤報來自外推規範 |

**不建議加的角色：** 「UX 標準」沒有獨有發現；挑剔版抓到的屬實條數明顯較多，誤報差不多。「功能排布」幾乎沒有獨有發現。不要派「資訊量」測試員，AI 讀全文不會累，抓不到訊息過多。

## 試跑學到的事

- 準備時間主要卡在登入：協調窗代為準備登入很慢，改成使用者自己登入後明顯縮短。
- 白箱對原始碼的精確率最穩；黑箱 UX、UI 的精確率較低，所以每條都要核對。
- 同一模組沒改動又跑第三次，新發現明顯變少。
- 有一輪最重要的發現是「雙擊會靜默存檔」：單元測試、E2E、人工驗收都沒抓到。用同一批回饋只讀碼回測時，這條被判成低，因為讀碼看不到它會寫入。**實機重現省不掉。**
- 雛形關：白箱先跑能先擋掉不少黑箱會重複回報的問題，所以白箱排第一；黑箱回報裡有相當比例屬於 mock 限制，要另外標。
- 雛形與 Playwright 攔 API 的 fixture 都看得到一部分設計層問題，但有些問題只有真環境看得到。

省下多少返工還沒量。

## 什麼時候值得跑

- **值得：** 新畫面第一次上線前、改版、要交付驗收、改動涉及操作流程。新畫面或流程改動在開發前再加跑雛形關，見 `prototype-gate.md`。
- **不值得：** 同一模組沒改動又跑一次。第三次起新發現明顯變少。
- **代替不了：** 真人測試。AI 不會累、不會猶豫，也不代表使用者。雛形關也代替不了實機測試，寫入後果在雛形上查不到。

## 證據等級

| 等級 | 誰產得出 | 能下的結論 |
|---|---|---|
| 檢查發現 | AI 測試員、白箱、協調窗 | 畫面有或沒有某個性質：有無返回路徑、空狀態有無下一步、點擊數 N |
| 使用者證據 | 只有真人測試 | 好不好用、看不看得懂、想不想用、會不會卡住 |

寫法範例：

- 不行：「使用者會不知道去哪改名。」
- 可以：「改名入口是沒有文字的鉛筆圖示，懸停 1 秒無提示，3 位測試員都沒有找到。」

## 嚴重度

只依可觀察後果，不依感受：

- **高：** 畫面上走不下去，或可能做錯不可逆的事。
- **中：** 做得完，但要用到畫面以外的知識，或有資料風險。
- **低：** 不順、不一致、可以再好一點。

測試員與白箱自評的嚴重度不採用，由協調窗統一定，改了寫理由。

| 例子 | 嚴重度 | 理由 |
|---|---|---|
| 不可逆動作沒確認，或按了沒提示卻已寫入 | 高或中 | 看影響範圍：影響所有人或無法復原給高 |
| 改名入口只有圖示，3 位都找不到 | 中 | 功能可用，但要畫面以外的知識 |
| 空畫面沒有下一步 | 中 | 同上；測試員都靠其他線索走完時可降為低，寫理由 |
| 編輯中按 F5 修改消失 | 低 | 專案規範沒要求離開確認時；有規範要求就是中 |
| 訊息出現時清單被推動 | 低 | 不順 |
| 提示字沒更新 | 低 | 不影響任務 |

## 指標

| 指標 | 算法 | 參考門檻 |
|---|---|---|
| 準備時間 | 開工到派工 | ≤30 分 |
| 非預定人工介入 | 預定的只有開工登入、收站登出、同意寫入 | 0 次 |
| 硬規則違反 | 看逐字紀錄，不信自報 | 0 次 |
| 精確率 | 屬實 ÷ 判定數，判定數已扣工具問題與 mock 限制，另列含部分屬實 | ≥80%（含部分屬實） |

門檻是自己訂的目標，不是業界標準。沒達標時寫原因，不要調門檻。
