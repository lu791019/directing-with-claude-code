# 踩過的坑

設計時對照一次，適用的寫進 `trial.json`。每條都是實際發生過的。

## 工具

| 現象 | 原因 | 處理 |
|---|---|---|
| 點按鈕後工具逾時，分頁卡死 | Chrome 工具操作不了原生 `prompt`、`confirm` | 列進 `native_dialog_actions`，測試員不按，協調窗代測。卡住就關分頁重開，等再久也不會恢復 |
| 測試員回報「沒有回饋」，其實有 | 提示訊息約 3 秒消失，截圖沒拍到 | 按儲存後下一個動作立刻截圖。這類回報先重現再判，曾有整批都是誤記 |
| `get_page_text` 讀不到提示框 | 它只讀頁面主內容，讀不到右上角浮層 | 不能拿它當「沒有提示」的證據，要看截圖 |
| 找得到按鈕卻點不到 | 被浮層或側邊選單蓋住，手機寬尤其常見 | 回報前先截圖確認，手機測試要用手機裝置模式 |
| `find` 被用來找畫面看不到的東西 | 等於偷看結構 | 只准定位截圖上看得到的元素，每次記一行 |
| 匯出時工具可能停在下載提示 | 下載屬於要明確許可的動作 | 把允許下載寫進使用者請求與 `authorized_writes`，註明檔案放哪、誰清。內容由協調窗檢查 |
| 截圖一直逾時，連簡單頁面也一樣 | 接管空白分頁後截圖失敗，換新分頁就正常 | 開新分頁再試，不要懷疑受測頁面 |
| 雛形的 `file://` 開不起來 | 內建瀏覽器不開本機檔案，Claude in Chrome 未驗 | 雛形一律走本機站 |
| `get_page_text` 讀到雛形的決議紀錄 | 附註和畫面在同一頁，每次讀取都讀得到 | 測試用 `prepare_prototype.py` 的複本 |

## 權限

| 現象 | 原因 | 處理 |
|---|---|---|
| 測試員存檔被自動模式擋下 | 分類器判定為修改共用資源 | 不要重試、不要拆開重送、不要換方法。記下來，該步驟列「未做（權限）」 |
| 協調窗轉述授權後，判定為繞過 | 轉達授權無效，還會被視為規避 | 派工前把授權寫進 prompt。仍被擋就請使用者自己處理，或調整權限模式 |
| 測試員一直跳權限詢問 | 逐步操作都要核准 | 整段流程改成單一腳本，在終端機跑一次 |

## 登入與環境

| 現象 | 原因 | 處理 |
|---|---|---|
| 開工才發現沒人有密碼 | 沒有事先準備，準備時間拖很久 | 使用者開工前自己準備好 |
| 協調窗讀種子檔代登入被擋 | 判定為探查憑證 | 協調窗不讀含密碼的檔案，使用者本人登入 |
| 分頁沒有登入狀態 | 使用者登在別的視窗 | 協調窗先開好分頁，請使用者在那個分頁登入 |
| 開工直接進到上一輪帳號 | 單一登入殘留 | 開工確認帳號。收站請使用者登出，並新開分頁確認落在登入頁 |
| 開工落在選租戶頁 | 單一登入殘留的另一種情況 | 請使用者自己選，協調窗不代點 |
| 點首頁後所有分頁都變慢 | 背景快取佔住同來源導航，會排隊很久 | 查清楚是哪個頁面，列進 `dont_click` |
| 主題或設定突然變了 | 同帳號的測試員互相影響 | 寫進 `not_issues` |
| 測了舊程式 | 站台跑的不是要測的版本 | 本機查 listener 的程式路徑；遠端查部署紀錄或問使用者。查不到就寫「版本未驗證」，列進開工檢查 |
| 不知道有沒有危險頁面 | `dont_click` 無從判斷 | 開工時由你先試，別先禁掉一大片，誤禁會讓測試員走不完任務 |

## 流程

| 現象 | 原因 | 處理 |
|---|---|---|
| 測試員靠已知清單得知操作方式 | 清單寫了做法 | 只寫現象，見 task-design |
| 故意犯錯汙染主要任務 | 順序錯 | 主要任務寫完才做，寫在任務開頭 |
| UI 測試員把設計分級報成不一致 | 不知道是刻意的 | 列進 `not_issues`，例如按鈕深淺、頁籤樣式 |
| 測試員自報的數字不準 | 憑印象 | 時間用系統時間，遵守度看逐字紀錄 |
| 白箱外推規範 | 條文用「例如」舉例 | 只有明確列出的才算不一致 |
| 多個 session 分不清 | 沒有固定編號 | 標題帶編號，回饋檔帶編號 |

## 報告

| 現象 | 處理 |
|---|---|
| 把 AI 意見寫成使用者反應 | 一律改寫成畫面事實 |
| 沒驗到的範圍被省略 | 獨立成一節，寫原因與影響 |
| 把比較基準寫成同環境 | 本機與站台、Debug 與 Release 分開講 |
