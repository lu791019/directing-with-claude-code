# 回收分析

順序不要調。先稽核再核對，遵守度有問題的回饋要降低採信度。

## 1. 收齊

需要的輸入：

- 各測試員的回饋檔，缺段就回頭問該測試員，不要自己補
- 各面向的 `prompt.md`、`tasks.md`：判斷規則邊界、用語差異都要對照
- `trial.json`：版本、站台、測試資料、授權範圍
- 測試當時的程式版本。工作區可能已經修過，查證要用 `git show <當時 commit>:<路徑>`

**沒有 `trial.json`，只有回饋檔時：** 問使用者版本、站台、測試資料。問不到就寫「未載明」，列進「未驗到的範圍」，遵守度寫「未核」，清理腳本不寫。

## 2. 稽核

跑 `scripts/audit_transcripts.py`，產出 `_coordinator/audit.md`，看：

- 用了禁止的工具沒有
- 網址列輸入了不允許的網址沒有
- 讀了資料夾以外的檔案沒有
- 被權限擋下幾次，是哪些動作
- 實際開始、結束時間

腳本只抓機械性訊號，列出來的要人工看是否真的違規。找不到逐字紀錄時，寫「遵守度未核」，不要寫 0 次。

## 3. 逐條核對

判定單位是**有編號的回報條**。測試員自標「觀察，非問題」的、表格裡沒編號的觀察，不計入判定數；有價值就併入相關條目。補充任務的回報照算。

| 判定 | 意思 | 計入精確率分母 |
|---|---|---|
| 屬實 | 畫面確實如此 | 是 |
| 部分屬實 | 現象存在，但描述、原因或範圍有誤，寫明差在哪 | 是 |
| 不成立 | 重現不出來；或事實屬實但設計文件明定如此（註明出處）；或任務卡用語造成 | 是 |
| 工具問題 | 工具限制，不是畫面問題 | 否 |
| 未能核對 | 沒有環境或資料可查證，列「待重現」 | 否 |
| mock 限制 | 只用於雛形：現象存在，但來自雛形機制或示範資料，帶不到需求與正式版。判法見 `prototype-gate.md` | 否 |

證據層級：

- **A**：你親自在畫面或 DOM 實測
- **B1**：原始碼直接證明該畫面性質，例如文字就寫在那裡
- **B2**：只證明機制存在，或多位測試員一致，畫面未證實

先核這幾類，誤報最多：

1. 「沒有回饋」：先重現，動作後立刻截圖。
2. 工具逾時後的現象：多半是原生對話框。
3. UI 不一致：可能是刻意的分級。
4. 用語與任務卡不同：任務卡是協調窗寫的，不算畫面問題。

### 要查到後果的回報

下列回報不能只憑讀碼定案，**要親自重做一次，查實際寫入了什麼**：

- 連按、雙擊、按鈕位置在操作後改變
- 畫面沒提示，但可能已經存檔或送出
- 測試員的描述前後矛盾，或寫「有時候」
- 被任何人判「只是不順」，但動作會寫入資料

查法：操作前後比對資料（修改時間、筆數），並查出機制。

實例：幾位測試員回報連按時點擊落到別的按鈕，只讀碼會判成低，而且推不出後果。親自重做後查資料庫，修改時間更新了，原來雙擊「編輯版面」的第二下落在儲存鈕，靜默寫入，嚴重度升為中。這是該輪最重要的發現。

沒有瀏覽器做不到這件事時，判「未能核對」，列入建議優先重現，不要自己定低。

### 沒有瀏覽器時

只能核到 B1、B2。用測試當時的版本讀原始碼，A 級留空，報告開頭寫明，並列出需要實機重現的條目。

## 4. 去重與編號

- 同根因合併成一條，保留所有來源：`L1 H-03、L2 H-03、W1-12`。
- 黑箱合併後依嚴重度連續編號 `G-01` 起；白箱獨有的保留 `W1-xx`。
- 既有缺陷另外標，不算這次引入。可用 `git diff` 確認。

## 5. 定嚴重度

依 `method.md` 的判準由你統一定，可以改動測試員與白箱的自評，改了寫理由。

## 6. 算精確率

判定數＝原始數 − 工具問題 − 未能核對 − mock 限制。UX、UI、白箱分開算。白箱的 100% 是對原始碼，不是畫面重現，要註明。

測試員中途換人（例 L3 中止由 L3b 接手）時，兩位的回報都計入同一面向，在比較表註明。

有多個模型時比「各自獨有且屬實」的條數，不是比總數。派工條件不同就寫「不足以比較模型優劣」。

## 7. 核對已知清單

- 已知問題還在的列出來，看有沒有修好的。
- 測試員重複回報已知問題，不算新發現。

## 8. 寫報告

照 `assets/report-template.md`，每段都要實際數字。任務未完成要分原因：畫面問題、權限擋下、原生對話框、測試員中止；雛形另有「結果沒畫或未接線」。

檢查：

- 全文搜尋「使用者會」「看不懂」「困惑」「覺得」。出現在報告本文就改成畫面事實，或移到待真人測試。
- 精確率分母對得起來。
- 沒驗到的範圍有獨立一節。
- 高、中的每一條都有重現步驟與核對結果。

**預防沒做到時：** 事前沒列的原生對話框、被權限擋下的動作，事後補不回來。列進「未驗到的範圍」，寫清楚缺了什麼覆蓋，以及建議怎麼補測。

## 9. 清理

列出測試資料：類型、編號、內容、是否刪除。資料來自 `trial.json` 與測試員回報的改動清單，缺的請使用者補。

寫好清理腳本後先給使用者看，同意才執行。資料庫操作要包交易，執行前備份，執行後回讀筆數。

收站確認：服務停了、工作區乾淨、使用者已登出。
