# 開 session 指引

目標是使用者不用懂細節，照你一步一步走就能開完。一次只給一個動作。

## 開工檢查

逐項確認，全部過才派工：

- [ ] 站台在跑，版本是要測的版本。自己起的站要確認程式來自正確的目錄。查不到版本就記「未驗證」。
- [ ] 測試資料建好，每位測試員一份。查詢型功能略過。
- [ ] 試一次 `dont_click` 列的頁面，確認真的要禁，沒有誤禁任務必經的路。
- [ ] Claude in Chrome 已連線，工具可用。
- [ ] 由你在那個 Chrome 開好受測站台的分頁，請使用者**在那個分頁**登入。
- [ ] 登入後你截圖確認帳號正確。
- [ ] `authorized_writes` 已寫進測試員的 prompt。
- [ ] `status.md` 已記下開工時間與版本。

請使用者登入時，同一句話一併問要不要同意寫入，少一輪來回。

登入分頁要由你先開好，因為使用者常登在另一個視窗或設定檔，測試員的工具看不到那份登入。

雛形不用登入與測試資料，開工檢查改成：`prepare_prototype.py` 跑過、本機站的 listener 指向 `site/`、附註不在畫面上、Claude in Chrome 已連線。

## 開 session

**雛形要分兩次開：** 先開 W1，修完雛形與需求文件，重跑 `prepare_prototype.py`，再開黑箱。`launch.md` 已照這個順序排。

### 環境有 `start_session` 工具

先問一次：「要我直接開 L1、L2、L3、W1 嗎？會在側邊出現 4 個 session。」使用者同意後，一位一個：

- `initiation`：`user_asked`
- `context`：`fresh`
- `cwd`：該測試員的資料夾，W1 用 repo 根目錄
- `use_worktree`：`false`
- `model`、`effort`：照 `trial.json`
- `title`：`AI黑箱試跑 <編號>（<面向>）`
- `prompt`：`請讀本資料夾的 prompt.md，照裡面做。`
- `background`：一句話說明這是 UX 黑白箱試跑的測試員 session，只能照 prompt.md 做

`wake_when_done` 設 true，測試員結束就會通知你。

啟動後確認每位都有動作，再告訴使用者可以去忙別的。

### 沒有 `start_session`，或使用者想自己開

把 `_coordinator/launch.md` 裡的指引卡一張一張給使用者。每張只有四件事：

1. 開新 session
2. 資料夾選這個路徑
3. 模型與思考程度選這個
4. 貼上這句話

開完一張，等使用者回「好了」再給下一張。

W1 的資料夾是受測 repo，`prompt.md` 在測試根目錄，所以第一句話帶完整路徑。session 讀不到時，請使用者把 `prompt.md` 全文貼進去。

## 同時開幾位

- L1、L2、L3 可以同時跑，共用同一個 Chrome，各開自己的分頁。
- W1 不用瀏覽器，任何時候都能跑。
- 建議全部一次開完，環境狀態才一致。

## 跑的過程

| 測試員問的 | 怎麼回 |
|---|---|
| 帳號、測試資料在哪 | 直接回答 |
| 規則怎麼解釋 | 直接回答 |
| 這個按鈕是做什麼的、下一步在哪 | 不回答，請他照畫面判斷，記下卡住的地方 |
| 工具逾時、分頁卡住 | 照 prompt 的脫困規則，記進工具問題 |

測試員被權限機制擋下時，不要叫他換方法重試，也不要轉述使用者授權。記下來，事後由使用者本人處理。

## 補充任務

要換身分（例如一般使用者）時：

1. 主要任務都收回後，由你切換帳號或權限。
2. 只派一位做補充任務，用另一個檔案寫任務。
3. 問題編號接續，寫進同一份回饋檔。
4. 切換會動到權限資料時，先記下原值，做完加回，加回後再確認一次。

## 回報給使用者

派完講清楚三件事：跑了哪幾位、大約多久、使用者接下來要不要做事。一位黑箱測試員跑完 5 項左右的任務通常是幾分鐘的事，整輪含核對與補驗要以小時計。任務多或畫面慢會更久。
