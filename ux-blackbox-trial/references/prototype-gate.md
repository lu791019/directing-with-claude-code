# 雛形關

受測物是還沒開發的雛形時讀這份。其餘步驟照 SKILL.md。試跑心得在 `method.md`。

目的是在開發前抓設計層問題：名稱、入口、流程斷點、需求矛盾、需求沒定義。它不取代實機測試，寫入後果、連按、後端驗證都留給實機關。

## 整體流程

1. PM 做完雛形，跑雛形關並修正。
2. 工程師開發完，跑實機黑白箱並修正，見 `live-gate.md`。
3. PM 真人驗收，最好再找一位沒參與需求的同仁點一次。

只有新畫面或流程改動才跑雛形關。小異動不值得。

## 雛形關順序

1. **白箱先跑**，對照需求文件。
2. 修雛形與需求文件，翻案的決策要記錄。
3. **再跑黑箱**。不能省，有些需求缺口只有黑箱碰得到。
4. 修正後才送客戶。

高、中條目轉成待確認事項，低級不擋開單。雛形關不設「通過」，它只產出要處理的問題。

## 編制

| 編號 | 面向 | 派不派 |
|---|---|---|
| W1 | 白箱對照需求文件 | 預設 |
| L1 | UX 挑剔 | 預設 |
| L3 | UI 視覺 | 畫面密集才派 |
| L2 | UX 挑剔（對照） | 不派，它的價值在犯錯路徑，雛形沒有 |

## 準備

1. `trial.json` 設 `target: prototype`、`prototype_source`，範例在 `assets/trial.prototype.example.json`。`start_url` 用 `http://127.0.0.1:<埠>/proto.html`，不要用 `file://`。
2. W1 的 `files` 放 body 片段、`.feature`、grill，`standards` 寫要對照的文件。
3. 產生資料夾與測試複本：

   ```bash
   python <skill 目錄>/scripts/scaffold_trial.py <測試根目錄>/trial.json
   python <skill 目錄>/scripts/prepare_prototype.py <測試根目錄>/trial.json
   ```

4. 照 `prepare_prototype.py` 印出的指令起本機站，用 `get_page_text` 確認給人看的附註與切換模式鈕都不在畫面上。各雛形的段名不一，看到新段名就補進腳本的 `SECTION_WORDS`，重跑後才派工。
5. 修完雛形後重跑 `prepare_prototype.py`，再派黑箱。

複本是給測試員用的，原檔不動。這幾段留著會洩題：決議紀錄會直接寫出控制項名稱，工程師筆記會寫出預期行為。

異動雛形的藍框（`.proto-changed`，框角是 CHG 編號）也會在複本拿掉，框裡的內容保留。藍框標的是跟現況不同的地方，留著會把測試員直接引到新功能上。黃框（OQ）保留，測試員的 prompt 已經說明。

## 任務卡

寫法照 `task-design.md`，差異如下：

- 不做故意犯錯。雛形沒有防呆邏輯，`scaffold_trial.py` 會擋。
- 不靠前後依賴。雛形存不了資料，後面的任務不能用前面的結果。
- 寫得出結果的就問結果，例如「找出原因」，答案要在畫面上。
- 反悔任務照做，用來看流程有沒有退路。
- 測試員遇到沒接線的按鈕記「已找到，未接線」。這條和控制列、黃框的說明已內建在 prompt，不用寫進 `not_issues`。

## 判定

照 `analysis.md`，多一種判定 **mock 限制**：現象存在，但來自雛形機制或示範資料，帶不到需求與正式版。不計入精確率。

| 回報 | 判定 |
|---|---|
| Esc 不關彈窗 | mock 限制 |
| 取消後表單殘留、選單關不掉、頁籤高亮不動 | 雛形工具新版已修。舊版組的雛形算 mock 限制；重新組裝後還在，就記在版面與雛形品質層 |
| 每一列開到同一份彈窗內容 | mock 限制 |
| 文件要求的結果畫面沒畫 | 屬實，要補 |
| 文件之間矛盾，或文件沒定義但畫面碰得到 | 屬實，要回寫需求 |
| 沒接線的按鈕本身 | 不算問題；該有的結果沒畫才算 |

發現分三層記：**設計層**（要改雛形或需求）、**版面與雛形品質**（改雛形時順手處理）、**mock 限制**。只有設計層算雛形關的成果。

修正時雛形、`.feature`、grill、規格摘要要一起改。只改雛形會留下矛盾。

## 不支援的 mock

**Playwright 攔 API 的 fixture 不適用這套流程。** 攔截和假登入只存在 Playwright 自己開的瀏覽器裡，Claude in Chrome 碰不到；換成 Playwright 工具時稽核腳本認不得，會稽核出假的 0 違規。而且無狀態，連續任務走不下去。

它適合給白箱當截圖來源，以及補真環境難造的失敗態、空狀態、權限、長資料。要跑黑箱就用真環境。
