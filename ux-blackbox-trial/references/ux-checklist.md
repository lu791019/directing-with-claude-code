# UX 走查清單（白箱用）

W1 逐條判定。每條只准三態：**通過＋證據**、**缺陷＋證據**、**N/A－理由**。

怎麼查：🖱＝要操作瀏覽器；🔍＝讀原始碼。白箱不開瀏覽器時，只有 🖱 的條目寫「N/A－需瀏覽器」。

🔍 只能證明機制存在，🖱 才證明畫面看得到。

| # | 項目 | 怎麼查 |
|---|---|---|
| U-01 | 寫入有回饋：成功時有提示或畫面變化，失敗時有訊息 | 🖱🔍 |
| U-02 | 載入不跳版：載入前後主要區塊位置不動，背景更新不閃爍 | 🖱🔍 |
| U-03 | 進行中可見：送出鈕有進行中狀態，長作業有進度或文字 | 🖱🔍 |
| U-04 | 同一動作同一動詞：按鈕、標題、麵包屑、確認框用詞一致 | 🖱🔍 |
| U-05 | 狀態用詞與顏色一致，不單靠顏色傳達 | 🖱🔍 |
| U-06 | 有返回路徑：麵包屑可點，手機有返回，直接貼網址也回得去 | 🖱🔍 |
| U-07 | 可中途離開，離開不留資料。有離開確認時要說明會遺失 | 🖱 |
| U-08 | 主要動作明確，每個容器最多一顆，位置一致 | 🖱🔍 |
| U-09 | 清單頁標題與選單項目文字相同 | 🖱🔍 |
| U-10 | 不可逆動作先確認，並說明後果。寄信、通知也算 | 🖱 |
| U-11 | 送出前擋得住：必填有標示，標示與驗證一致 | 🖱🔍 |
| U-12 | 空狀態有下一步，不指名沒權限的人看不到的按鈕 | 🖱🔍 |
| U-13 | 限制事前說明，不是失敗才知道 | 🖱🔍 |
| U-14 | 清單狀態可還原：返回或重整後篩選與頁碼不歸零 | 🖱🔍 |
| U-15 | 錯誤說得出怎麼修，落在對的位置，不露出技術代碼 | 🖱🔍 |
| U-16 | 鍵盤走得到：Tab 可達、焦點可見、順序照視覺，彈窗焦點正確 | 🖱🔍 |
| U-17 | 新流程成本合理：畫面數、點擊數、中途離開不靜默遺失 | 🖱 |
| U-18 | 首次使用：什麼都沒設定時，說得出缺什麼、去哪補 | 🖱🔍 |
| U-19 | 真實資料量：長名稱、多筆資料不撐爆，截斷後仍分得出來 | 🖱🔍 |
| U-20 | 無權限畫面：被擋時說得出原因，沒有按了才失敗的按鈕 | 🖱🔍 |

專案有自己的規範時以規範為準，寫進 `trial.json` 的 `whitebox.standards`。已登記的既知限制標 N/A，不重複開缺陷。受測物是雛形時，只能靠實際行為判定的條目標「N/A－雛形不含」。

來源：Nielsen 十項啟發式，依實際走查調整。
