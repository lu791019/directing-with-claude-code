# 快取保溫

## 為什麼要保溫

主線的 prompt cache 要靠主線自己發請求才會續期，有效期約 1 小時。子代理是另一個對話，跑再久也不會幫主線續；使用者離開時主線完全不動。

閒置超過有效期，下一次叫醒主線時整段 context 要用寫入價重讀；保溫喚醒一次只是用讀取價讀一遍，便宜很多。內容不會丟，差的只是錢，所以這是省錢手段，不是安全手段。

## 兩種用法

| | 等子代理 | 我要離開（hold） |
|---|---|---|
| 怎麼開 | `/keepwarm`（不帶參數） | `/keepwarm 2h`、`90m`、`15:30`，或「保溫兩小時」 |
| 喚醒時做什麼 | 看還有沒有背景子代理在跑 | 看到期了沒 |
| 什麼時候停 | 子代理都回報了 | 到期，或使用者回來說「撤保溫」 |
| 上限 | 子代理跑完為止 | **8 小時**。更久就寫交接檔、開新視窗，比硬撐划算 |

同一時間只開一個保溫排程。

## 怎麼開

1. 取現在時間，分鐘數記為 `m`。
2. 排兩個相隔 30 分鐘的分鐘點：`a=(m+25)%60`、`b=(m+55)%60`，碰到 0 或 30 就加 1（避開整點、半點的尖峰）。
   不要排每小時一次：排程會有幾分鐘誤差，間隔可能超過有效期。
3. hold 模式先算到期時間：時長就加上去；時刻就是今天那個時間（已過就是明天）。超過 8 小時就建議改寫交接檔。
4. 用排程工具建一個每小時 `a,b` 分觸發、會重複的排程，喚醒內容照下面的固定字串（字串固定，喚醒時才不會順手做別的事）：

   等子代理：
   ```
   【keepwarm 子代理】只做這件事：查還有沒有進行中的背景子代理。
   有 → 只回「等待中」，不讀檔、不做其他工作。
   沒有 → 刪掉以【keepwarm 子代理】開頭的排程，回「保溫已撤」。
   ```

   hold：
   ```
   【keepwarm hold 到 yyyy-MM-dd HH:mm】只做這件事：取現在時間。
   還沒到 → 只回「保溫中（到 HH:mm）」，不讀檔、不做其他工作。
   到了 → 刪掉以【keepwarm hold】開頭的排程，回「保溫已撤」。
   ```

5. 回使用者一句話：「已開保溫」或「保溫到 HH:mm，每 30 分鐘續一次，回來說『撤保溫』或到時自撤」。

## 什麼時候撤

- 子代理回報了，而且沒有別的背景子代理在跑：**先撤保溫，再做複驗**。
- 使用者說「撤保溫」：所有以【keepwarm 開頭的排程全撤。
- 忘了撤也沒關係：喚醒內容自帶檢查與自刪。

## 規矩

- 排程只在主線閒著時觸發，不會插隊。
- 排程跟著 session 走，關掉視窗就沒了；新視窗接手要重開。
- **喚醒那一輪不做任何工作**：不複驗、不讀檔、不整理。保溫輪越短越省。
- 跟主線共用前綴的 fork 子代理不用保溫，它自己的請求就會續期。
- 不要自動開：只有使用者明講才開。
